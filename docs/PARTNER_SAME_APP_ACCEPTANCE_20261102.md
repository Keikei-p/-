# 営業実績管理アプリ — 自社・協力店の本番受け入れ条件 (2026-11-02)

## 不変仕様（ユーザー確定）
- **一つのWebアプリ／一つのログイン画面／同じ画面レイアウト／同じ操作**。協力店専用アプリ、新たな会社コード認証、代表者必須登録は作らない。
- 自社と協力店の違いは会社の所属と財務権限だけ。**協力店は売上・単価・財務原票を画面・API・Firestoreのいずれからも取得不可**。自社の従来の売上・単価表示は変更しない。
- 自社オーナーが会社名＋招待メール、必要に応じて班・リーダー／メンバーを指定する。**Firebaseから招待メールを自動送信 → 本人のメール認証 → 新規利用者が初回パスワードを設定 → メールとパスワードでログイン → 既存アプリに参加**。メールアプリ手動送信は正式仕様ではない。
- 協力店も自社と同じ実績入力、修正、日別、班別詳細、商材別、登録履歴、ランキング、班・メンバー管理の画面と操作を持ち、金額要素だけ非表示（表示しないだけでなく読み込み禁止）。
- 自社側「班別詳細」に協力店枠を設け、**会社名 → 班 → 担当者 → 商材別件数**を表示する。各社の所属を混ぜない。
- 全社「個人ランキング」と「商材別ランキング」は自社＋協力店を合算し、**件数・順位のみ**表示する。協力店を一人の架空担当者として表示しない。二重計上は禁止。
- 既存アカウントのUIDと当時単価・売上・履歴・班履歴、LINE自動報告、Firebaseの既存データを削除・初期化しない。
- 会社と班の権限チェックをサーバーで実施。協力店が他社実績を読めない。メール確認ができない人、無効招待、再送失敗は参加不可。

## このPRでコード修正済み（本番未適用）
- 招待メールの Firebase 自動送信と初回パスワード登録フロー（FirebaseメールリンクAuth設定は別途実環境確認が必要）。
- 自社の既存「班別詳細」に協力店会社別ツリーを追加。件数専用APIで「会社 → 班 → 担当者 → 商材」を必要時に取得。
- 協力店用に既存ダッシュボードと同じ8つのメニューボタンを設置。財務DOMと元の財務取得は引き続き隔離し、件数APIを表示。

## まだ未達・本番公開の停止条件
1. **合同個人ランキング**は既存コードが協力店を会社単位の仮想担当者にしており、個人別月間合算が未完成。商材別も、会社別集計のみに依存する古い部分が残る。
2. 協力店用の実績画面は既存ダッシュボードを模した構成になったが、**完全な画面／操作の一致は未達**。登録履歴は最終保存状態の表示で、訂正監査全件の閲覧には未対応。
3. Firestore Rulesの本番原票アクセス問題 [Issue #206](https://github.com/Keikei-p/-/issues/206) は未解消。UI上の非表示だけでは承認不可。
4. FirebaseのEmail link設定、実際の受信・ログイン・承諾・件数保存→自社反映のスマホ実アカウントE2Eは未検証。
5. 既存のFunctionsとHostingの公開順序、安全ゲート、金額表示の回帰確認が必要。旧ハッシュ固定のリリースワークフローは変更後に停止するのが正しい。無理に通さない。
6. 大量の件数／無料枠下での月間個人ランキング集約は、Firestore読み取りコストと二重計上を抑えた設計・検証が必要。

**このPRをmainへ統合すると既存自動Hostingリリースが発火しうる。未達解消前はDraftを保持する。本番公開済み・完成と報告しない。**
