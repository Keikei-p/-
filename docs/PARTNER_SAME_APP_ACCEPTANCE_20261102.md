# 営業実績管理アプリ — 自社・協力店の本番受け入れ条件 (2026-11-02)

## 不変仕様（ユーザー確定）
- **一つのWebアプリ／一つのログイン画面／同じ画面レイアウト／同じ操作**。協力店専用アプリ、新たな会社コード認証、代表者必須登録は作らない。
- 自社と協力店の違いは会社の所属と財務権限だけ。**協力店は売上・単価・財務原票を画面・API・Firestoreのいずれからも取得不可**。自社の従来の売上・単価表示は変更しない。
- 自社オーナーが会社名＋招待メール、必要に応じて班・リーダー／メンバーを指定する。**Firebaseから招待メールを自動送信 → 本人のメール認証 → 新規利用者が初回パスワードを設定 → メールとパスワードでログイン → 既存アプリに参加**。メールアプリ手動送信は正式仕様ではない。
- 協力店も自社と同じ実績入力、修正、日別、班別詳細、商材別、登録履歴、ランキング、班・メンバー管理の画面と操作を持ち、金額要素だけ非表示（表示しないだけでなく読み込み禁止）。
- 自社側「班別詳細」に協力店枠を設け、**会社名 → 班 → 担当者 → 商材別件数**を表示する。各社の所属を混ぜない。
- 全社「個人ランキング」と「商材別ランキング」は自社＋協力店を合算し、**件数・順位のみ**表示する。協力店を一人の架空担当者として表示しない。二重計上は禁止。
- 既存アカウントのUIDと当時単価・売上・履歴・班履歴、LINE自動報告、Firebaseの既存データを削除・初期化しない。
- 会社と班の権限チェックをサーバーで実施。協力店が他社実績を読めない。メール確認ができない人、無効招待、再送失敗は参加不可。

## このPRでコード修正済み（本番未適用）
- 招待メールの Firebase 自動送信と初回パスワード登録フロー（FirebaseメールリンクAuth設定は別途実環境確認が必要）。
- 自社の既存「班別詳細」に協力店会社別ツリーを追加。件数専用APIで「会社 → 班 → 担当者 → 商材」を必要時に取得。
- 協力店用に既存ダッシュボードと同じ8つのメニューボタンを設置。財務DOMと元の財務取得は引き続き隔離し、件数APIを表示。

## まだ未達・本番公開の停止条件
1. **合同個人ランキング**は既存コードが協力店を会社単位の仮想担当者にしており、個人別月間合算が未完成。商材別も、会社別集計のみに依存する古い部分が残る。
2. 協力店用の実績画面は既存ダッシュボードを模した構成になったが、**完全な画面／操作の一致は未達**。登録履歴は最終保存状態の表示で、訂正監査全件の閲覧には未対応。
3. Firestore Rulesの限定修正は本番 [run 41377119717](https://github.com/Keikei-p/-/actions/runs/41377119717) で適用成功。続く読み取り専用 [run 41388293487](https://github.com/Keikei-p/-/actions/runs/41388293487) で現行Rules一致・255文書全件照合・本番文書書込み0を再確認した。**協力店の実UIDを使った原票アクセス拒否の実機検証は未完了**であり、UI非表示だけでは承認しない。
4. FirebaseのEmail/Password・Email Link・本番ドメイン設定は、本番GET検査 [run 41389210155](https://github.com/Keikei-p/-/actions/runs/41389210155) で合格。`passwordRequired=false` はproto3 JSONで省略されうるため、誤って無効と判定しない。**実際のメール受信・ログイン・承諾・件数保存→自社反映のスマホ実アカウントE2Eは未検証。**
5. 既存のFunctionsとHostingの公開順序、安全ゲート、金額表示の回帰確認が必要。旧ハッシュ固定のリリースワークフローは変更後に停止するのが正しい。無理に通さない。
6. 大量の件数／無料枠下での月間個人ランキング集約は、Firestore読み取りコストと二重計上を抑えた設計・検証が必要。

**このPRをmainへ統合すると既存自動Hostingリリースが発火しうる。未達解消前はDraftを保持する。本番公開済み・完成と報告しない。**


## 2026-11-02 追加実装・現行受入状況（最新）

- **同一アプリ・同一ボタンデザイン**：既存の本家ダッシュボード11ボタンを複製し、協力店用の「実績入力」カードを追加。ボタンを押した列のすぐ下に対象パネルを展開し、従来の「最下部だけに表示」を廃止。財務パネルは表示・読込しない。
- **2列の件数入力**：本家の `product-input-list` / `product-input-group` / `record-save-button` を再利用。件数合計、0件報告、入力クリア（保存前データだけ）を実装。保存後に再取得・版数と件数を照合。
- **管理メニュー**：「招待リンク」「商材追加・管理」「班管理」「メンバー管理」「会社」「アカウント設定」を独立導線化。招待は班・メール・leader/member指定。Firebaseメールリンク本人確認は維持。
- **協力店独自商材**：会社内プライベート商材の追加・非表示・再表示、件数入力・訂正、過去件数の保持。代表者必須ではないので協力店リーダーに自社内だけの管理権限を付与。通常メンバー・別会社・自社Hubから操作不可。協力店専用商材は全社ランキングへ混ぜない。
- **登録・訂正履歴**：協力店の監査行を日付選択・履歴タブ表示時だけ読み取る。権限と会社で範囲を絞り、読取上限超過は部分成功と見なさない。
- **合同ランキング・班別詳細**：既存の `sharedRankings:true` 件数専用APIを維持し、直営＋協力店の会社・班・実在担当者・商材の**日別**件数を共通表示。UID不明の直営過去記録は件数を残し、架空の個人は作らず「未照合」を明示。

**未解決の公開ブロッカー（この文書の先行する「まだ未達」は本節で更新）：**
