## 1. 既に確定したUI/運用

自社Leader・協力店Leaderは同じ営業実績アプリ / 同じナビ・班詳細・メンバー登録・日週月・商品入力・件数ランキングを使用する。自社金融データは自社の既存権限のまま、協力店には**APIから一切渡さない**（CSS非表示だけでは不十分）。

- 共通UIは既存index.htmlのpartnerInlineWorkspaceと自社Leader画面をベースに接続する。
- 既存の自社recordsおよびpartnerWorkEntries/partnerWorkCountDays、修正履歴・獲得日・班/人の保存時点所属を維持する。別DB移行や同内容の複製は禁止。
- 保存は同じフォームでも自社側は既存の金額検証済み処理、協力店側はサーバー認証済みsubmitPartnerWorkspaceCountsを引き続き使う。
- 自社Ownerの商材管理ON/OFFを入力許可とランキング公開の正本にする。名称一致の旧商材は確認済みSKU対応へ、曖昧な「つばさ・HTB」等は未連携のままOwnerに提示する。過去は削除しない。
- 2026-11-18以降、SB光とSB AIRは新規入力上別々にするがランキングはSB光・AIRの既存1枠で合算。旧合算分は旧未分類としてそのまま残す。**PR #798は未公開Draftのため本番動作はまだ未確認。**

## 2. 既存協力店実績の扱い（読み取り層だけの統合）

| Firestore既存正本 | 読み取り/保存の方針 | 共通画面・報告での表示 |
| --- | --- | --- |
| partnerWorkEntries | 個人日別原票を維持、1件を1回だけ読む | 獲得日・当時の班・スタッフ・公開ON商材の件数 |
| partnerWorkCountDays / reports | 個人行と合計一致を検証。原票を二重加算しない | 会社の日別確定件数 |
| partnerQuickCountDays / reports | 個人情報がない旧報告は会社単位の未割当として保持 | 会社/商材件数には加える。班・個人の架空順位は禁止 |
| partnerWorkAudits | 訂正履歴の継続使用。履歴の上書き禁止 | Ownerが監査画面で照会 |
| rankingSkuMappings/shared | Ownerが承認した商材ID対応だけ | 旧商材が自社・協力店の同じ商材ランキング枠へ |
| rankingProductVisibility/shared | 協力店への公開ON/OFF正本 | OFFは新規入力をサーバー拒否、元の件数は保存 |
| 自社records/products/recordCorrections | 既存金融原票を変更しない | 自社権限のみ。協力店からはGET/LIST拒否 |

**明示したチェック**：
- 旧会社単位5件 + 新しいスタッフ別4件 = 会社9件、班や個人は確認済み4件だけ。旧5件は未割当。
- 同一獲得日のスタッフ集計と旧会社単位報告が両方ある場合は、同一原本か識別できない限りランキングを確定せず安全停止。恣意的な合計・自動移動は禁止。
- 報告済み0件と未報告を別状態で表示。OFF商材にだけ入力した実績を報告済み0件に偽装しない。
- 旧合算光/AIRをAIに推定分配させない。

## 3. AI自動報告の設計（最初にゼロ費用・件数のみ）

**既存コードを再利用**：reports/worker.mjs は9:30朝礼、19:05未報告、21:00最終の東京時間Cron予定、reports/format.mjs と reports/combine.mjs に金額なしLINE文面テンプレートがある。wrangler.sales-reports.toml の REPORT_DELIVERY_ENABLED は false。既存workerは通常のrecordsベースで、**新しい協力店partnerWorkEntriesを網羅することは未確認**。本番へ接続する前に件数正本を統一する。

今回新設：reports/verified-count-ai-briefing.mjs

1. **入力**：サーバーが本人認証・会社所属・公開ON/OFFとSKU対応・保存済み日報の整合を検証済みの nico-approved-partner-count-rank-v1 応答だけ。ブラウザの提出値、元のFirestoreデータ、価格原票は渡さない。
2. **集計**：会社・商材は実際の合計件数。班/個人は帰属を確認できた部分だけ。旧会社単位未割当、未報告会社、未照合があれば「一部未確定」と明示し、架空の順位や推定の「成長率」を作らない。
3. **レポート本文**：今日/週/月の件数、報告有無、上位商材・会社、確認済み班・個人（完全性確認できる場合のみ）。社内Owner用の自社＋協力店合同版は、**別途権限検証済み合同件数APIが本番で有効になってから**接続。partner-only応答を合同と偽称しない。
4. **AIへの最小入力**：原本・UID・個人名・会社名・単価・売上・CBを除いた集計件数・商材カテゴリ名・未報告数・旧未割当数だけ。言語モデルは所見文の提案のみであり、数字、入力結果、商品対応、ランキングの計算をさせない。AIの文章は件数に検証可能な根拠があるものだけ採用し、送信前にOwnerが確認できるようにする。
5. **最初の配信**：無料テンプレートから社内Owner向けプレビュー。外部LINE/メール送信、自動投稿、外部AIモデル呼び出し、顧客情報送信は**既定OFF**。配信先と時刻の明示的なOwner設定、二重送信ガード、通知先ごとのアクセス許可確認後に限定稼働。既存LINE配信の設定を勝手に変更しない。

1. 自社と協力店の画面の入力タブ/班詳細/メンバー/ランキングの配置・操作が同じ、協力店には金額APIのレスポンスさえ存在しない。

3. 0件報告・未報告・旧会社単位5件・新個人日報4件を区別して、会社合計9件と適切な未割当表示を一致させる。
4. ONで協力店入力→Owner件数確認→合同会社/班/個人/商材ランクが同じ獲得日に反映。OFFで書込み拒否・履歴保持。
5. 光/AIRは新入力個別・ランキング合算。旧データは未分類のまま。
6. AIレポートは金額等の混入を拒否し、無根拠な成長率・未確認の順位を出さず、未公開送信/有料API/Firestore書込みがない。
