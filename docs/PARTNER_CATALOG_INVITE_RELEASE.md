# 自社/協力店招待、共通商材・独自商材の安全仕様（2026-10-29）

## ユーザー確定要件
1. 招待リンク作成時に**自社メンバー**か**協力店（別会社）**を選択。既存社員は今までの所属のまま。協力店は自社と別のcompanyIdで作り、長期運用でも他社の元帳・売上・単価・CBを参照できない。メール確認/期限/一回限り/オーナー認可をサーバー側で強制。
2. **自社の商材一覧を正本**として協力店の実績登録画面に同じ商材名・表示順・商材IDで提示。自社の変更を自動的に反映できる。協力店に自社の商材の単価/売上/CBは一切配信しない。
3. 協力店が独自商材を追加したい場合、会社内で管理できる。**初期は他社非公開**。商材ごとに**「自社内のみ」⇄「連携先へ商材名・件数のみ共有」**のスイッチを設け、連携元との双方承認がある会社だけに公開する。価格・原票・顧客データの公開スイッチは設けない。
4. 朝夜のLINE・総合件数・班ランキング・商材別ランキングは**共有を承認した商材の件数を常時合算**。非公開商材の件数は相手の集計からも除外し、総件数の差から秘密の商材活動が推測されないようにする。協力店は自社内で自社非公開商材の件数を見られる。公開されない分を混ぜて「全部の件数」と偽らず、画面では集計範囲を示す。
5. 自社と協力店で商材IDが異なっても、中央共通商材は**元の自社商材ID**に紐づける。独自商材は**連携会社ID+商材ID**の複合キーで区別し、同じ名前だからという理由で勝手に統合しない。
6. 過去の実績、当時の単価、商材ID、班ID、会社ID、訂正履歴、旧PWAの挙動を**変更・削除しない**。新しい共通商材表示は正本の過去単価を再計算して上書きするものではない。

## 今回作成した実装部品
- \`partner/invite-contract.mjs\`: 招待を \`internal_member\` / \`partner_company\` で固定し、協力店作成は現在の自社Ownerのみ、30分失効・ユーザーの確認済みメール・一回限り・単価売上権限false・別会社ID作成・既存所属を変えないことを検証。既存の招待を途中で別目的へ変更できない。
- \`partner/shared-catalog.mjs\`: 現行 \`products\` 正本から**金額無しの \`publicProducts\` の投影**だけを生成。協力店側の独自商材は別コレクションで名前/順序/公開状態のみ、初期値private、オーナーのみpublic切替。公開側から独自private商材を返さない。
- \`filterPartnerCountLines()\`: プライベートな商材は他社への公開件数も除外（単純な名前マスクだけでは件数差から秘密が露見する）。
- いずれも今は**純粋関数の開発版**で、本番の招待UI/Cloudflare・Firebaseサーバー/本番Firestoreには未接続。GitHub mainにマージしてもユーザー向け画面は自動では切替わらない。

## 先行リリース禁止
本番の自社 \`products\` には価格・CBが含まれている。Firestore Rulesはフィールド単位で隠せない。新しい共有商材UIを作っても**元の自社 \`products\` を協力店へ直接読ませてはならない**。必ず金額なしの公開用データとバックエンド検証を利用する。

また「協力店」は単に自社の \`leader\` の名称を変えるものではない。**独立した会社に所属させる**。別会社招待の受け取りで既存ユーザーの \`companyId\` を勝手に変更せず、新会社設立が完了しなければ招待を失効させずに停止して原因調査する。

この開発PRは実Firebase/LINE/料金に書き込まない。各設定をユーザーがFirebase Consoleで手作業作成する必要はない。秘密鍵/招待トークンをGitHubに載せない。
