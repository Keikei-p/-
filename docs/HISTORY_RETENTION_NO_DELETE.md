# 営業実績・履歴の物理削除防止（安全確認 / 未公開）

## 目的
過去の実績・売上金額・単価情報・班・商材・目標を、一般メンバー、リーダー、オーナーの誤操作や古いWeb画面によって消失させないこと。

## 変更内容
- Firestore Security Rules で `records`、`teams`、`products`、`goals`、`revenueGoals` の**クライアントからの物理削除を一律拒否**。
- `recordCorrections` は既存の更新・削除禁止ルールを維持する。
- Web画面から実績・班・商材の「削除」ボタンと物理削除処理を除去。新規登録、実績訂正、目標編集、班名編集、商材マスターの通常編集は維持する。
- `tests/rules.test.cjs` で一般メンバー・班リーダー・オーナーの削除拒否と、データが残ること、編集が続けられることを確認。

## 意図的に残す機能と制限
- 正当な実績訂正は引き続き可能であり、元の実績内の金額・件数を変更できる。訂正前後ログの原子的保存を必須とするPR #106は別途検証・統合が必要。
- **現在のアプリに過去データの復元・ロールバック・操作履歴の完全な保全機能があることを意味しない。**
- Firestore Security Rules はモバイル/Web SDK経由のアクセスを制御する。Firebase Admin SDK、Cloudflare Workerの特権サービスアカウント、Firebase Console管理者の操作にはRulesが適用されないため、IAM権限分離とクラウドバックアップは別に必要。
- 既存の `teams` と `products` のルールは「無効化」へ変更する操作をまだ用意していないため、不要になった班・商材を画面から隠す正式な運用は別途対応する。無理に消さず残す。
- 社員のAuth退職・アカウント削除、招待コードの期限切れ/削除は対象外。事業データは別IDで保存し、ユーザー削除からの連鎖消去をしない。
- 旧コードで動作中の画面は、Rulesだけ先に変更すると「削除」がエラーになる。新旧URLの画面、PWA、Rulesの同期とテストが必要。
