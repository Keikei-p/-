# 年次売上資料・アーカイブの安全運用手順（開発版 / 未公開）

## 目的と出力
会社・年度ごとに売上を月別、班別、商材/CB別、個人別に整理し、オーナーが印刷（PDF保存）、CSV、復元可能な原本JSONとして保存する。

| 分類 | 内容 |
| --- | --- |
| 年次・月次 | 年度総合売上、1〜12月の月別売上・件数、保存時単価からの差 |
| 班別 | 原則その日の登録先teamIdに帰属。廃止・移動後の実績を新しい班に移さない |
| 商材別 | 商材ID、CB別件数、再計算時の単価情報、保存時単価との比較 |
| 個人別 | uidに紐づく年間売上。**オーナー専用資料のみ**。一般の個人ランキングは「順位・名前だけ」 |
| 元データ | レコード・商材マスター・班・当年度目標の読取スナップショット。保存時のrevenuePerUnitも保持 |

### 金額の基準
表示用「再計算売上」は資料作成時点の承認済み商材マスターとCBプランの単価×獲得件数。確認できない旧CBプランは保存時単価を利用し、**フォールバック件数を明示**。商材不明、単価不明、無効件数、同一担当者・同一日付の複数レコードは安全停止し、レビューを要する。既存のFirestore原本・保存時単価・過去CBは上書きしない。

## 操作手順
1. オーナーでログインし、対象年度を選択する。取得前にアプリ本体の売上・商品CB、班帰属を確認する。
2. 「年次レポートを確認」で月別・班別・商材別・個人別の金額と相違件数を確認する。
3. 「印刷・PDF保存」で見やすい資料を保存し、「CSVを保存」で表計算ソフト向けファイルを確保する。
4. **前年以前の確定年度のみ**、「確定した前年以前を保管」でPrivate R2へ改ざん検出付き原本を新規保存する。
5. 自動の再読込・SHA-256照合が通った後、保存一覧で「保存資料を開く」から復元表示を検証する。
6. 「原本コピーを保存」からJSONをダウンロードし、R2とは独立したオフライン／別サービスの保護された場所へ保存する。原本を第三者へLINE・メール送付しない。
7. 月・班・商材・個人の合計と原本件数、CB単価の一致を確認し、承認記録とchecksumを残す。

## セキュリティとコスト
- APIはマスター/オーナー権限をサーバー上の所属user/member/companyから再取得して判定する。協力店・一般メンバーには金額・原本アクセス不可。
- R2バケットは**非公開**。パブリックドメインを設定せず、認証済Owner Gatewayの署名検証を経由して参照する。R2は暗号化保存の対象だが、端末へコピーしたJSONにも同等のアクセス制御が必要。
- デフォルト `FINANCE_GATEWAY_ENABLED=disabled`, `FINANCE_COST_APPROVAL=NOT_APPROVED`, `FINANCE_ARCHIVE_APPROVAL=NOT_APPROVED`, `FINANCE_ARCHIVE_WRITE_APPROVAL=NOT_APPROVED`。Private R2バインディングは承認後のみ追加。料金はFirebase/R2/Workers各無料枠と超過課金の別途確認を要する。
- 12MB超の年次原本はサーバーメモリ安全性により停止する。過大データは年度→月別ストリーミング・分割アーカイブが必要。100,000件/collectionの総読込安全上限も残る。
- 同じcompany/year/hash keyへ上書きは行わない。年度を再集計すると別の版になることがある。毎版のハッシュを保管する。

## 絶対に実施しない操作（本機能には存在しない）
- アーカイブ完了をもって、Firestoreの元実績・商材・目標を自動削除する処理
- Firestore Security Rules の即時切替
- 本番実績の売上・件数・過去単価の訂正
- 協力店への元売上金額・バックアップ原本の共有

## 本番リリース阻止条件
1. 独立したバックアップ2媒体が存在し、1件・複数件の復元と合計・ID一致を検証できない。
2. 同一年度中に商材単価を変更した場合の差異（とくするでんき、エバーグリーン、NURO CBなど）を実データで検証できない。
3. Cloudflare Workerによる複数Firestore collectionの取得時点のずれ、同時更新、請求上限・実バケット動作・暗号化・CORS・データ公開範囲を確認していない。
4. 協力店がFirestore生レコードの収益フィールドを取得できる既知リスクが残っている。
5. 新旧URL・iOS/Android/PWA・Owner/Leader/Member/Partnerすべての導線を検証していない。

**この設計段階では上記条件が未達であり、Draft PRからmainへマージ・本番デプロイしない。**
