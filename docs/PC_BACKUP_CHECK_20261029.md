# 既存バックアップの検算とローカル隔離復元（Windows PowerShell）

**既存データを一切削除しないで、PCで次の手順だけ実施するための準備済みツール。** このコードは本番FirebaseのURL、Rules、Auth、社員情報に接続しない。

## 1. バックアップファイルを保管
- `.salesbak` は暗号化したローカル原本。GitHubのリポジトリ外の安全なフォルダへ置く。
- 暗号化パスフレーズは本人だけが管理し、GitHub/チャットに書かない。
- この検証は**元バックアップを上書きせず、他人へファイルを送らない**。

## 2. PCに戻ったら（リポジトリのルートで）
```powershell
powershell -NoProfile -File .\scripts\verify-sales-backup.ps1
```
実行中に `.salesbak` の絶対パスとパスフレーズを入力。既存の保存ファイルの復号整合性、ドキュメントID・件数・商材ごとに保存した件数の突合を**オフライン**で実施。機密情報を個別に画面表示しない。

## 3. さらに隔離した復元を試す（Firebase CLIとJavaがPCに必要）
```powershell
powershell -NoProfile -File .\scripts\verify-sales-backup.ps1 -RunLocalRestore
```
Firebase CLIを使い `demo-sales-restore` の **127.0.0.1 ローカルエミュレータだけ**に書き戻し、ID・フィールドを全件再読込して照合。実FirebaseのID `sales-management-cc116` と外部ホストはコードで拒否する。既存本番DBには絶対に復元しない。

初回のFirebase CLI導入が必要な場合は（Windowsの個人PCのみ）：
```powershell
npm install -g firebase-tools
```
ネットワーク接続・ダウンロードが必要な可能性がある。既に導入済みなら不要。復元を省略すればCLIは不要。

## 検証限界とリリース禁止条件
- 既存バックアップが最新の本番全件を含むか、Firestoreと厳密に同一時刻か、Auth・Cloud Storage・設定を含むかは、この検証だけでは証明できない。
- 隔離したローカル復元は最大**50,000文書**（8並列・127.0.0.1のdemo環境限定）。25,001文書の架空データで処理・全件照合のテストを追加。50,001文書以上は最初の書込み前に安全停止する。本番データの復元実証ではない。
- 元Firestoreのレコード、単価、CB、売上、班履歴の**削除・再計算・一括移行は禁止**。
- このファイルの存在や単体テストPASSだけで「本番バックアップ復元完了」と言わない。本人PCで実際に実行した成功ログ、別保存先のバックアップ、現在のFirestoreの収益/件数/権限比較が残る。
- 同じ日に他の営業入力があればバックアップの差分は正常な場合もある。自動差分修復しない。

**作業者の手元では本番Firebaseの資格情報・実データを確認できていないため、実バックアップの検算・隔離復元は未実施。**
