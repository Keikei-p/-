## 1. 開発目的・確定原則

1. 自社と協力店の件数を同一管理画面から参照する。
2. 自社Ownerが承認済み協力店を選択し、**既存登録済み**件数を監査付きで訂正する。
3. 自社Ownerが商材ごとの協力店公開ON/OFFを設定し、協力店の入力可否を画面**とサーバーの両方**で強制する。
4. 自社・協力店を合同集計し、商材・班・個人の3ランキングを表示する。
5. 協力店画面は自社ダッシュボードと基本デザインを共通化する。ただし金額関連機能は除外する。
6. 協力店から自社の売上・単価・CB・過去金額原票へのアクセスを遮断し、既存実績・件数・履歴・所属を保護する。

**画面は自社用と協力店用の2種類、データと件数集計の基準は共通化する。**

## 3. 構成・正本データ

**認証:** Firebase Authentication + 承認済み既存認証経路。**処理:** Cloud Functionsによる権限判定、件数入力・訂正、商材設定、ランキング。**保存:** Firestore。**画面:** Firebase Hosting（スマホ対応）。**防御:** Firestore Security Rules + 許可リスト型API。

自社Owner → 自社ログイン → ダッシュボード → 協力店管理 → 会社選択 → 班/スタッフ件数確認・訂正 → 商材設定 → 合同ランキング。

協力店Owner/Leader/Member → 協力店画面 → 許可商材の件数入力 → 自社へ件数共有 → 公開範囲の合同ランキング。

**既存正本を優先して再利用する。** 別画面のために件数の独立した第二正本を作らない。ランキング用派生データは正本から検証生成し、未完全部分データでランキング確定しない。

| 保存先 | 用途 |
| --- | --- |
| `companies/{companyId}` | 会社 |
| `users/{uid}` | 所属 |
| `companies/{companyId}/members/{uid}` | 会社別権限 |
| `partnerRelations/{partnerId}` | 自社↔協力店承認関係 |
| `companies/{partnerId}/partnerWorkTeams/{teamId}` | 班 |
| `companies/{partnerId}/partnerWorkStaff/{staffId}` | スタッフ |
| `companies/{partnerId}/partnerWorkEntries/{date}__{staffId}` | 日次スタッフ別件数 |
| `companies/{hubId}/partnerWorkCountDays/{date}/reports/{partnerId}` | 自社側会社別日次報告 |
| `companies/{partnerId}/partnerWorkAudits/{auditId}` | 訂正履歴 |
| `companies/{hubId}/rankingProductVisibility/shared` | 商材公開ON/OFF |
| `companies/{hubId}/rankingSkuMappings/shared` | 商材ID対応付け |

自社の金額付き実績は既存 `records`・`products` 等をそのまま保持する。会社別サマリーをスタッフ別明細と**二重加算しない**。

## 4. 認証と権限

サーバーがリクエストごとに以下を確認する:
1. 有効なFirebase IDトークン・必要な再検証
2. アカウントが無効化されていないこと
3. `users/{uid}` の有効所属
4. 有効な自社 `companies/{companyId}`
5. 有効な `companies/{companyId}/members/{uid}`
6. 本人がその自社Ownerであること
7. 対象協力店との**承認済み・現在有効**な関係

クライアントが送る `role` / `hubCompanyId` を権限根拠にしない。自社Ownerは**協力店の認証情報を入手・共有・偽装せず**、所属も変更せず、管理API経由で協力店を操作する。

| 操作 | 自社Owner | 自社Leader | 協力店Owner | 協力店Member |
| --- | --- | --- | --- | --- |
| 自社金額 | 可 | 既存権限の範囲 | 不可 | 不可 |
| 全承認済み協力店の共有件数 | 可 | 許可範囲 | 他社分不可 | 他社分不可 |
| 協力店の既存件数訂正 | 可 | 初期OFF | 自社分の既存権限 | 原則不可 |
| 商材公開ON/OFF | 可 | 不可 | 不可 | 不可 |
| 班・メンバー管理 | 可 | 承認範囲 | 自社分 | 役割に応じる |
| 合同ランキング | 可 | 可 | 公開承認範囲 | 公開承認範囲 |

エラーを `AUTH_REQUIRED`, `EMAIL_UNVERIFIED`, `OWNER_NOT_AUTHORIZED`, `PARTNER_RELATION_MISSING`, `FUNCTION_UNAVAILABLE`, `DATA_SHAPE_INVALID`, `NETWORK_ERROR` に分類。画面には安全な日本語、ログにはエラー分類とリクエスト識別子のみ。トークン・パスワード・金額原票をログに残さない。既存 `getPartnerWorkspace` を先に検証し、不足の場合のみOwner管理専用の件数コンテキストAPIを検討。

## 5. 画面

### 自社

既存「ダッシュボード」「実績管理」「管理設定」を維持し、「協力店管理」「商材公開設定」「合同ランキング」を追加。既存ナビゲーション・売上表示・入力を削除しない。

Owner管理入口: `/owner-partner-admin.html`。上部は自社/協力店の件数サマリー・日付切替・再取得。中央は承認済み協力店カード。会社選択後は会社合計、班別、スタッフ別、未報告、訂正ボタン。下部は監査履歴・管理導線。**1タップ会社選択、再ログイン不要**。A→B切替時はAの編集状態を破棄してBだけ再取得。未報告を0件と偽らない。

### 協力店

自社ダッシュボードの基本カード配置・操作感をできるだけ再利用し、「件数・許可商材・班・メンバー・件数履歴・公開範囲ランキング」だけを表示。売上・単価・CB・利益・金額グラフ・金額目標は**表示しない／APIにも返さない**。

## 6. 件数保存と訂正

`partnerWorkEntries` 既存 `companyId, hubCompanyId, date, staffId, teamIdSnapshot, counts, totalCount, version` 等を維持。0以上の整数、商材別合計と総件数の一致、会社/日付/本人のサーバー照合、保存時班スナップショット保持。未報告行を表示目的で0として作成しない。

協力店保存は `submitPartnerWorkspaceCounts` を優先。本人・班・スタッフ・日付・公開商材・版番号・合計・承認関係をサーバー検証する。

Owner訂正は `listHubPartnerCounts` / `correctHubPartnerCounts` を再利用:
1. Ownerサーバー認証、承認関係再検証
2. **既存の**スタッフ・日付行を取得
3. 現在件数と `version` を表示
4. 新件数・必須訂正理由・`expectedVersion` を送信
5. 競合拒否付きFirestore transactionで明細と会社日次合計を整合更新
6. `partnerWorkAudits` に訂正前後・理由・実行者を追記
7. 保存後再取得・対象日/月キャッシュ無効化

会社全体の件数直接上書き、他者履歴削除、売上原票更新は**禁止**。**新規代理登録**は別機能として設計（専用権限・重複防止・作成者記録）。既存訂正APIに無理に作成権限を追加しない。

## 7. 商材公開ON/OFF

Owner管理で商材ID・名称・自社マスタ有効状態・協力店公開状態・会社別例外・設定版・更新者/日時を扱う。基本は自社から協力店全体へのON/OFF、必要に応じ会社別例外。

- ON: 協力店入力画面に表示、保存APIで許可、件数を共有、**承認済みSKUマッピング**を経て合同ランキングへ。
- OFF: 通常入力画面に非表示、**サーバーで新規入力拒否**、既存件数・過去履歴・訂正履歴は保持。過去ランキング除外は別途明示操作と承認が必要。
- `rankingSkuMappings/shared` を使ってOwnerが商材ID対応を承認する。商材名類似のみで自動統合しない。「未統合」は明示し、件数は消去・誤配分しない。
- SB光/Air旧合算は現行互換を保持。分離は将来の新規入力から版付き仕様で扱い、過去の合算を自動分割しない。
- 旧APIの固定9商材制約を無視しない。新商材はバージョン付き定義・入力API・検証・集計を一体で拡張する。

## 8. 合同ランキング

正本 `records`（自社の件数に必要な許可データのみ）と協力店 `partnerWorkEntries` から商材別、班別、個人別の**同じ集計基盤**を構成。会社日次サマリーは明細との照合に使い、二重計上しない。

- 表示モード: 合同（初期値）/自社のみ/協力店のみ。期間: 日/週/月。
- 件数降順、同数は同順位、0件だけなら優勝演出なし、未報告は0件として順位付けしない。
- 同名でも会社・班・スタッフIDで区別し、過去日は保存時スナップショットを使用。
- 協力店に公開する個人ランキングは**初期は順位と承認済み公開名称/ニックネームのみ**。個別件数は別権限、Owner管理画面のみ許可件数内訳を閲覧できる。
- 保存・訂正・承認解除・公開設定変更・SKU承認変更で該当日/会社/月の派生集計を無効化。
- 全件正本照合、金額フィールド無し、未承認会社/商材無し、明細合計＝総件数。部分取得や不整合ならランキング確定を停止。

## 9. API再利用と応答契約

| API | 役割と原則 |
| --- | --- |
| `getPartnerWorkspace` | 協力店一覧と共有件数。まず既存認証問題を調査 |
| `submitPartnerWorkspaceCounts` | 協力店件数入力、既存入力を保持 |
| `managePartnerWorkspace` | 班・スタッフ管理、既存処理保持 |

| `getOwnerReviewedSkuMapping`, `setOwnerReviewedSkuMapping` | Ownerによる商材ID承認 |
| `getVerifiedJointCountRanking` | 金額なし合同ランキング、初期OFFから安全接続 |

共通応答は「成功（対象・件数・版・確認状態）」「未報告」「権限なし」「再ログイン必要」「競合」「API停止」「データ不整合」を区別。秘密情報・金額原票をエラーで返さない。

## 10. 金額遮断・防御

協力店から自社 `products`, `records`, `recordCorrections`, `revenueGoals` のGET/LIST・不正書き込みをRulesとサーバーで遮断。UI非表示だけで完了としない。

同一メールで旧自社/現協力店の二重所属があっても既存ユーザー情報・過去履歴は**削除しない**。協力店として利用中に旧所属の金融権限で読み取れる経路を拒否する。既存 `secondary-finance-read-fence.mjs` 候補は実ユーザー・Emulator・既存件数入力を検証後のみRules切替。

Authトークン・ユーザー無効状態・会社/班/本人・承認失効をサーバー検証。公開APIは許可リスト型件数のみ。ログイン/会社切替で表示キャッシュを消去。訂正は追記監査、公開キャッシュに金額原票を保存しない。

## 11. 本番化Phaseと合格条件

**Phase 1 認証・Owner管理:** エラー7分類、既存Ownerセッション、`getPartnerWorkspace`権限と応答、メニュー入口、会社1タップ。**合格:** 再ログインなしで承認会社の件数を閲覧し、未承認他社を拒否。

**Phase 2 登録済み件数訂正:** 2 Functionsの実配備/feature flag確認、本人の読取検証、既存件数訂正、理由/版/監査、競合とサマリー一致。**合格:** 該当スタッフだけ変更され、元売上・他社・履歴不変。

**Phase 3 商材ON/OFF:** マスタ/固定商材の対応、Owner設定保存、UI・保存API双方の制御、承認SKUマッピング、旧形式互換。**合格:** ONのみ入力でき、共有件数をOwner閲覧、OFFでも履歴保存。

**Phase 4 合同ランキング:** 既存集計に正本を接続、自社/協力店検算、商材/班/個人共通化、承認/公開/期間フィルター、双方画面と訂正反映。**合格:** 明細と合計一致、協力店APIに金額なし。

**Phase 5 最終金額遮断・公開:** READYバックアップ本体の隔離復元、実Owner/協力店Owner/Memberで権限試験、GET/LIST拒否、件数入力維持、旧URL/PWA互換、段階Rules切替、公開後監査。**合格:** 件数・訂正・ランキング正常、金融原票拒否、既存実績無傷。

各Phase: **コード修正→オフラインテスト→Emulator→GitHub CI→本番事前確認→限定公開→本人実証→公開後監査**。コード完成、Function配備、feature ON、本人動作、本番公開は別判定。

## 13. リリース・障害・データ保護

**禁止:** 過去件数/売上/単価/CBの初期化、既存レコード無断移行・削除、Functionsまとめ上書き、全Hosting無条件再配備、認可未確認代理操作、バックアップ未検証破壊的変更、CI成功だけで「本番完成」と宣言。

## 16. 実装の判断基準

「2つの画面を持つ1つの件数共有・管理システム」。自社Ownerは自身の認証のまま協力店を管理。協力店は許可商材の件数のみ入力し、自社との共同ランキングを共通正本から構成。金額は自社側に閉じ、履歴・所属・件数を保護して段階本番化。**設計変更、重要な例外、公開権限拡大、既存データ移行はOwnerの明示承認を要する。**
