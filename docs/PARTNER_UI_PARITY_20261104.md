# 協力店画面を自社と同じ操作感へ（未公開）

## 対象
公開HTMLと一致確認済みの `ccfef10600fc1d979013b8cd6520ae5b3ff1d5f1` を起点にしたUI限定修正。未公開の認証削除・移籍・Rules候補は含めない。

## 変更
- 自社と同じ順序：ユーザー情報、案内カード、独立した実績入力カード、ダッシュボード。
- 実績入力の余白・角丸・合計欄・ボタンに自社の既存CSSを使用。PCの日付/班と担当者/現場を2列、狭い端末では既存の共通レスポンシブ設定へ追従。
- 商材2列とCB別入力を保持。合計は件数のみで、売上/単価欄は追加しない。
- 自社と同じ11個のダッシュボードカードを同じ順序・スタイルで使用。売上分析/収益グラフ/売上順は件数の表示に置き換える。入力カードの重複メニューを除去。
- パネル再配置時に元のフォームを移動し、複製・初期化しない。再マウント時にも詳細ノードと入力値を保持。
- 協力店の集計期間は従来どおり選択日。見た目をそろえるために日次件数を月間件数と表示する変更はしない。

## 保全
自社側HTMLのユーザー情報以降からscript開始までの完全一致を確認。売上計算、単価、実績保存、API、Firestore Rules、Functions、Auth、LINEには変更なし。金額付き原票へ接続する処理を追加しない。

## 確認
- 業務・UI・売上維持・件数保存・未保存値保持など180テスト成功。
- HTML内JavaScript構文チェックとgit diffチェック成功。
- 本番へ接続しないローカルサンプルで390px/1280pxを確認。横はみ出しなし。
- CB2万円区分へ3件入力し、班詳細を開く→閉じる後も3件が保持される。元自社ダッシュボードは協力店では非表示。
- サンプルは既存の画面コードを使用し、Firebase SDKを除去、connect-src 'none'で本番通信を禁止。実績保存/招待は無効。

## 残る条件
本番未反映。AGENTS.mdの全件保全照合と権限別ログイン確認、既存手動公開ゲートを満たしてからindexのみの反映を判断する。UI金額非表示は維持されるが、既存Issue #206の二重所属UIDからの原票読取経路はこのUI修正では解決しない。別のRules候補PR #358の承認・検証が必要。
