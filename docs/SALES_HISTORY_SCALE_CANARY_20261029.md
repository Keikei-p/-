# 営業実績：2,000件超でも過去履歴を消さないためのSpark用読み込み試験版

## 原因
2026-10-29確認時点の本番 main は、`index.html` の `recordsCollectionQuery()` を使う Firestore `onSnapshot` / `getDocs` で会社の**全期間の実績原票**を購読する。2,000件は Firestore の保存上限ではないが、増えると読み込み・メモリ・無料枠消費が増す。2,000件超でアプリの売上/件数を「最初の2,000件だけ」集計してはいけない。

## 開発した試験切替
- Firebase Spark とブラウザ SDK だけで使用可能な**指定月の実績のみリアルタイム購読**を `index.html` に追加。
- 通常モードは既存の無制限全期間購読のまま、明示的な `?history-preview=1` を付けている**オーナー**のみに試験切替。協力店とマークされたアカウントは試験切替不可。URLパラメータ自体は権限を増やさない。
- 月変更前に古い合計・ランキングを一旦消し、対象月を会社ID/日付で確認したサーバーSnapshotだけを表示。Firestoreキャッシュや未同期のSnapshotは「確定」としない。
- 既存日付の編集は本人/日付でサーバーから読み直し、登録時の重複防止・訂正許可は従来どおり。保存後に表示を再購読。
- 年次グラフは対象年だけサーバーから別取得し、読み込み未完了時には年次合計を表示しない。年次読み込みは手動（タップ時）のみ。
- 実績・金額・単価・CB・会社/班/メンバー履歴は書き換えず、新規データ移行・バックアップ削除や自動保存期間処理も行わない。

## 公開を止める条件
1. **本番データの全件バックアップ・別DBでの復元・照合**は未実施。変更前の全件数/売上/単価/CB/訂正履歴/班履歴を比較する必要あり。
2. Firestore ステージングで `records` の `companyId` 昇順・`date` 昇順の複合インデックスを作り、権限別（owner/leader/member/partner）・新旧URL・iOS/Android PWAで動作確認すること。インデックス不備時に無制限全件読み込みへ**自動フォールバックしない**。
3. **同月に非常に多数のデータがある場合は、現在の試験版の月単位 onSnapshot も端末負荷が増える。** 1か月1万件以上、年間数十万件の運用には、ページ分割（250〜500）と月別集計の検証済みサーバーAPI、非公開データ分離を別途段階実装する。バックエンド側の25,001件ページングテストは別PR #102にあるが、この試験モードとはまだ直結していない。
4. date / companyId を持たない古い Firestore 原票は選択月のクエリに出てこない。全件原票の項目存在・旧データの監査をして、隠れた原票があれば**無断で変更せず公開停止**とする。
5. 会社別・協力店別の売上/単価をFirestore Security Rulesで完全遮断する最優先課題が未解決の間は、協力店に本番財務原票へのアクセスを付与しない。
6. 年次グラフも対象年の全件読み取りになるため、年次集計用の検証済みサマリ資料を導入するまで、頻繁な年次切替時の無料枠消費に注意。
7. Protected change gate / Sales App Validation / プレビュー実機試験 / 管理者の独立承認後にだけ機能を一般向けONへ。現行の `index.html` を本番用に差し替えたり、mainへマージしたりしない。

## Firestore index 候補（自動適用しない）
```json
{
  "indexes": [
    {
      "collectionGroup": "records",
      "queryScope": "COLLECTION",
      "fields": [
        {"fieldPath": "companyId", "order": "ASCENDING"},
        {"fieldPath": "date", "order": "ASCENDING"}
      ]
    }
  ],
  "fieldOverrides": []
}
```

**注意:** 複合インデックスが作れたこと自体は、正確な権限/単価/件数、漏洩防止や無料枠維持の証明ではない。

## 完了判定
- 2,000 / 2,001 / 25,001件で単価・CB・件数・日付の整合性。
- 同じ担当者・同じ日付が重複しない。過去の訂正履歴を保持する。
- 過去月へ切り替え→正確に取得→現月へ戻る→1件新規登録→差分一致。
- 年次/個人/班/商材別/合同ランキングの全件照合と、オフライン・遅い通信・インデックス未構築で部分集計を出さない。
- 旧GitHub Pages URL、新Firebase Hosting URL、古いPWAキャッシュを使う利用者の互換性。
