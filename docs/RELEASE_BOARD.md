## 【新たに確認】無料枠と月25,001件の読み取りリスク（2026-10-29）

Firestore Standardの**無料枠は50,000ドキュメント読み取り/日**（[Firebase公式](https://firebase.google.com/docs/firestore/quotas)）。`#125` の月別 `onSnapshot` は「全期間→選択月」の改善だが、選択月に25,000件あれば1回の完全取得で概ね25,000文書の読み取りが発生する。複数ユーザー/更新/再起動で無料枠を容易に消費するため、**現在の#125を「無料運用まで完成」と判定しない**。

本番に必要な残追加設計は次のとおり。
1. 月/会社/班/商材/個人の月次集計を**サーバー側で増分更新**し、画面は少数の集計ドキュメントを読む。財務金額付き集計と協力店の件数専用集計は**物理的に別コレクション/権限**にする。
2. 個別の履歴は日付・月・担当者で絞ったカーソル式（例: 100～500件）で取得。詳細を開かない画面で全原票を購読しない。
3. 既存の過去原票は**削除/上書き/推定再集計しない**。別環境の完全復元・原票照合後に、別の月次サマリを安全に生成/突合する。途中失敗なら元原票を保持し、サマリは「未確定」と表示。
4. Firestore利用量・1日50,000読み取り予算、請求アラート、許可済み社内画面/協力店画面の実機アクセスを確認してから本番へ。
5. **0件・部分ページ・キャッシュ表示を正しい確定値として表示しない**。一度に読める量の制限で合計値が失われる設計は禁止。

**#125のコードはmainへ統合済みだが、上記のコスト・集計正確性の条件を満たすまで正式リリースNO-GO。**
