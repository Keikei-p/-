# NICO FACTORY｜営業実績管理の会社向けURL切り替え手順（2026-10-22）

## 結論：本番データの移行・コピーは不要

| 利用先 | URL | 運用 |
| --- | --- | --- |
| 会社向け / 今後の案内先 | https://nico-factory.web.app/ | 通常利用の第一候補 |
| 旧 / 緊急時の確認先 | https://keikei-p.github.io/-/ | 消さずに並行維持 |

両方とも同じ本番の `index.html` が配信される構成で、**単一のFirebaseプロジェクト `sales-management-cc116` のAuthenticationとFirestore**を使用する。2つのFirestoreに同期しているわけではない。だから既存の実績ID、件数、CB価格、売上、班履歴、メンバー、会社IDを**コピー/移行/初期化/再登録しない**。

- 両URLでブラウザのオリジンとログイン状態は別。新URLでは初回に**同じアカウントで再ログイン**すること。FirebaseのDBは共有なのでログインし直しても実績はそのまま。
- PWA（ホーム画面へ追加）は別々のURLとして登録される。新URLをスマホのSafari/Chromeで開き、ログインして実績を確認してから新URLをホーム画面に追加。旧URLのアイコンは当面削除しない。
- 招待リンクは現行UIの `window.location.origin` に基づき作るため、新URLから招待すると新URLへのリンクが作成される。既発行の旧URLへの招待は無理に書き換えない。失効/期限切れは発行者へ依頼。
- URL変更だけではFirestoreの閲覧権限が厳格化されない。**金額付きドキュメントの直接読取りリスクは現行ルールに残る**。保護版PR #73はバックアップ・実機テスト・料金確認が完了するまでマージ/公開禁止。
- `index.html`、`firestore.rules`、`firebase.json`、`.firebaserc`、`service-worker.js` にこのPRで変更なし。

## 何が完了済みか

- Firebase Hostingサイトとして新URLを作成し、静的ファイルだけを同じリポジトリのmainから同期するワークフロー `.github/workflows/nico-factory-sync.yml` を導入済み。
- URLを使った実際のログイン・閲覧は依頼者の端末で一通り問題なしと報告あり。ただし全権限での実機検証は未了。
- 新設の無認証・読取専用テストで、6つの公開ファイル（index.html、manifest、Service Worker、180/192/512pxアイコン）を、双方のURLおよびリポジトリのmainとSHA-256で一致チェックできる。**Firestoreデータには一切接続しない**。
- `.github/workflows/nico-readiness.yml` は毎日4回、NICO Hosting同期完了後、アプリ画面・PWA等をmainに更新した直後に無認証チェックする。公開サービスの更新タイミングのずれは最大4回の短い再検査で吸収し、それでも差異が出るとGitHub Actionsを失敗にする。Actionsの実行遅延・通知設定の有無により、即時検知/自動復旧は保証されない。
- ファイルを読み取って比較するだけ。Firebase/Google Cloudの秘密鍵は新ワークフローに一切渡さず、CloudflareやFirestoreにはデプロイしない。

## 利用前に手動で確認すること（本人の端末、実データ更新はしない）

1. 旧URLと新URLに**同じメールアドレスのアカウント**でログインできる。
2. 1年以上前/前月/今月の実績と班履歴・商材内訳が新URLで表示され、旧URLと一致すること。
3. オーナー、売上閲覧許可ありの社員、許可なしの社員、他班のリーダーで閲覧の範囲が期待どおりか確認する。**UI上の非表示はセキュリティの証明ではない**。
4. 「✏️ 訂正」ボタン、対象日・担当者・班表示・価格プランが期待どおりか確認する。**本番では試験用の保存や削除を行わない**。
5. 新URLをホーム画面へ追加後、起動/再ログイン/スリープ復帰からの再読込を確認する。以前の旧URLのキャッシュがそのまま動くかも確認。
6. 開発者はFirestoreの別環境エミュレータで、日付・班・件数・単価・売上と履歴の訂正を検証する。

## 運用上の切り替えと復旧

- **会社への正式案内先は新URLで統一**し、まずは小人数で試してから全員へ案内する。新URLでログインができない場合は、既存の旧URLで状況確認。旧URLも問題があれば実績の編集・削除やルール変更を中止し、原因を確認する。
- URL切り替えに伴うFirestoreデータのエクスポート、インポート、二重書き込み、会社IDの再採番、商材金額の再計算は実施しない。
- GitHub mainと両公開サイトのコードバージョンが不一致の場合、本番Rules変更やセキュリティ移行を止め、Hosting静的同期ジョブとGitHub Pages公開履歴を確認。
- **HTMLの戻し操作はデータベースの復元ではない**。過去実績は推測で復元/再計算しない。バックアップの取得・復旧テストは別作業。
- 新しいFinances Gatewayの安全版PR #73はDraftのまま。2026-10-22時点で本番Firestoreバックアップ/全件ハッシュ照合、実機の全権限テスト、Cloudflare無料枠確認が未完了。
- 旧URLの停止/転送やリポジトリ改名は、全員の新URL移行が確認されるまで実施しない。今回も実施しない。
