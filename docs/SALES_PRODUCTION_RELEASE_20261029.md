# 営業実績アプリ — 本番公開 GO / NO-GO 判定 (2026-10-29)

**現在判定: NO-GO。** この文書と `scripts/production-readiness-audit.mjs` は準備用で、Firebase・Firestore・Hosting・Cloudflare・LINE・実績データには接続も変更もしない。

## 絶対に守る条件

1. `records`, `products`, `recordCorrections`, 班履歴、過去の単価、CB、会社・会員・招待・通知設定等を推測で移行・一括変更・物理削除しない。
2. 協力店（代表owner/master/leader/memberを含む）へ金額を返さない。画面非表示では不足。直接Firestore SDK、旧PWA、キャッシュ、Rules、サーバーAPIからの原票read/writeの全経路を閉じる。
3. 旧GitHub Pages URLは公式運用対象外。公式URLは `https://nico-factory.web.app/` のみ。**旧URLの公開停止は利用中の認証/キャッシュ/リンク調査後**に別作業とする。
4. LINEを既定OFFのまま準備し、送信先・課金/無料枠・再送・朝/夜/未報告の統一ON/OFFを確認後に初めて試験送信する。
5. GitHub mainへのマージはFirebase本番データの安全を意味しない。Rules/Hostingの公開は別途明示承認し、PR保護ゲートを迂回しない。

## 公開順序（全て満たすまで公開しない）

1. **現在の本番を読み取り専用で棚卸し**：現行Hosting/Rules/indexes/Cloudflare設定とそのリリースSHA、稼働中のAuthユーザー・会社・実績/訂正・班・商材・通知・提携関連コレクション/サブコレクションを一覧化。既存のバックアップが「Firestore全体」を含むか実物で検証（売上4コレクションのみでは不足）。
2. **独立した2媒体へのフルバックアップ・隔離復元**：JSON/CSV/PDFの数字が一致してもFirestore丸ごとの復元証明ではない。生のドキュメントID、型、会社ID、件数、現在/当時の単価、CB、削除拒否、訂正ログ、会社/人/班参照整合性を試験環境で比較。Authユーザー、Rules、Indexes、Storage、Secretsは別途保全/復旧計画とする。
3. **安全な件数専用経路を完成**：サーバー側のFirebase token署名・失効・最新所属・現行班/提携を確認。入力/訂正を原子的に書き、金額・価格を持たない公開ビューを同時更新。失敗時は途中結果を見せず停止。偽装companyId/uid/role/単価/CBを拒否。
4. **金融原票Rulesの遮断**：読み取りだけでなく、`get/list/create/update` の各経路（重なるmatchや旧クライアントも含む）を隔離エミュレータで検証。協力店代表者にも原票を渡さない。社内owner/masterの金額機能を維持し、会社間の漏えいも拒否。順番を間違えると現場入力不能になるため、画面とGatewayを先に試験してから切り替える。
5. **読み取り件数と履歴の負荷を調整**：対象月と対象会社だけ取得。古い日付の訂正・月越え・年越え・25,001件の合成テスト。実会社データの形式差異（旧date未設定・会社ID欠落など）を事前監査。無料枠/請求の承認なしにデータ取得を無制限化しない。
6. **通知・合同順位・年次保管は別々に安全切替**：LINEは送信OFFで検証開始。年次出力後もFirestore原本は自動削除しない。順位は金額/件数そのものを返さない。
7. **新URLで権限別スモーク試験**：社内owner/leader/member、協力店owner/leader/member、無効ユーザー、他会社、未ログインで、ログイン→登録→訂正→過去月閲覧→報告→年間資料→ログアウト→再ログインを iPhone/Android/PC で確認。PWA旧キャッシュを考慮。
8. **管理者リリース審査**：バックアップのハッシュ・隔離復元結果、アクセス拒否証跡、件数/売上照合、無料枠、公開差分、各PRのCIと手動確認を記録。PR保護ゲート、権限独立レビュー、承認後にのみmainへのマージと公式URLへの手動公開を行う。

## 家のWindows PCでの最初の確認

開発用リポジトリの当該ブランチを取得できたら、リポジトリ直下で下記を実行する。

```powershell
node scripts/production-readiness-audit.mjs
```

- 読み取るのはローカルの `firestore.rules`、`index.html`、ワークフロー設定、件数用Gatewayだけ。
- Firebaseトークン・サービスアカウント・パスワード不要。データ更新、バックアップ削除、デプロイ、外部ネット接続なし。
- 結果は **STOP** が正常な安全動作。静的検査だけで本番OKとは判定しない。修正・実機・バックアップ復元の証跡を別途確認。
- GitHub Actions無料枠不足の場合でも、このローカル点検自体はNode.jsのみで実行できる。エミュレータ・本番接続テストは別途必要。

## 問題発見時

公開を停止し、本番Firestoreに書き込み/一括復元を行わず、対象SHAと公開中ファイルを確定して原因調査。Hostingのみのロールバックが可能でも **Rulesの単純な差戻しは漏えいを再開させる恐れがある** ため、協力店アクセスを停止してから独立審査する。
