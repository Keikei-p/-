# 営業実績アプリ｜データ非破壊での段階公開（2026-10-28）

## 最重要
- 実績 `records`、売上金額、単価、CB条件、班履歴、商材マスターの**既存ドキュメントIDを変えない**。
- 本番データの一括更新・削除・移行・復元操作は禁止。実際のFirebase本番バックアップを同じデータベースへ復元しない。
- 会社別分離、協力店の金額・単価閲覧不可、既存アカウント、旧URLを必ず再検証してから公開。
- ドラフトPR・テスト合格のみでは本番完了ではない。GitHub Protected Change Gateの未承認を回避しない。

## 対象の開発PRと公開条件
1. **#109 実績訂正/退職者/利用終了**：件数・当時金額・元IDを変更せず、実績の訂正と監査ログを同一トランザクションに保存。離職者は管理者処理で利用停止。班と商材の物理削除を禁止したまま利用終了/再開を用意する。
2. **#110 会社共通の商材グループ**：共有設定がなければ既存の端末内設定を使い、会社オーナーが保存した時だけ共通設定へ。実績・単価に変更なし。
3. **#105 協力店の件数専用アクセス**：公開用コレクションの所属班制限はエミュレータで確認。**本番の旧`records/products`が金額入りのまま読み取れるため、#105の試験用Rulesを単独本番適用してはいけない。** 認証済みサーバーから件数だけ投影し、旧APIを閉じる切替計画が必須。
4. **#100 売上順位だけ（数値なし）/ #101 と #107 LINE自動報告 / #102 大量件数ページング / #103 と #104 年間保存**：重複するブランチのまま一括マージしない。利用中のアプリと原票を変えず、機能別に検証して順次公開する。

## チーム履歴の安全性
- 現行Firestore Rulesでは、本人の班変更とteamHistory更新を許している。勝手に過去履歴を書き換えるリスクは残る。
- 自己変更の履歴をリストの追記だけに制限する試作では、Firestore Emulatorでルール式の評価上限に達し、正常な班変更も拒否された。
- **不合格の実装はPR #109から取り消した**。現場の班変更を止めたり過去履歴を壊したりする変更を本番へ入れない。
- 改修案: 管理者承認済みサーバー経由で班変更を受け付け、現在の班・履歴・会社所属を同じトランザクションで確定。前の履歴は保持し、元データは読み取りだけ。匿名化した実績でエミュレータから再検証する。

## 禁止操作
- バックアップを検証せず本番原票を削除
- 保存・転記ができたという理由だけで原票を消す
- 効率化のために会社全員に財務原票の読み取りを開放
- 金額を隠しただけで協力店の権限が安全と宣言
- チャット内のユーザー承認を、GitHubの本人署名・第三者レビューの取得済みと偽装
